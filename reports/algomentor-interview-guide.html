Interview introduction, three lengths

20 seconds

“AlgoMentor is a competitive-programming coach built with Next.js and FastAPI. It imports Codeforces and LeetCode profile data, turns it into topic analytics and study plans, and offers AI tutoring and code review. PostgreSQL stores learner data; JWTs protect the API.”

45 seconds

“I built AlgoMentor to help competitive programmers identify weak topics and plan practice. The Next.js client uses a typed API wrapper and TanStack Query. FastAPI routes delegate to services and SQLAlchemy repositories backed by PostgreSQL. Users sign in with bcrypt-hashed passwords and access/refresh JWTs. Profile sync pulls Codeforces and LeetCode data; analytics, recommendations, and rating predictions use the stored result. Gemini powers tutoring and code review when an API key is set.”

90 seconds

“The core user journey is register, sign in, link a coding profile, then inspect dashboard analytics and generate practice guidance. The frontend uses Next.js App Router with client components for interactive pages. A shared fetch client attaches an access JWT and refreshes it after a 401. FastAPI validates the token, loads the user, and invokes a service. Profile sync fetches Codeforces REST data plus LeetCode data through a third-party stats API and LeetCode GraphQL, normalizes submissions and topic tags, then replaces the profile's derived rows in PostgreSQL. Other services produce charts, rule-based roadmaps and recommendations, and request-time rating forecasts. The AI endpoints use Gemini if configured, with static fallback output otherwise. Redis currently tracks revoked refresh-token IDs; it does not cache dashboard data. I can also explain the limits: localStorage tokens, serial external calls during sync, synthetic LeetCode rating history, and development-focused Compose settings.”

IMPLEMENTEDRefresh validates JWT type, Redis denylist status, stored token expiry/revocation, and active user; it revokes and blacklists the old token before creating a new pair. Logout revokes the supplied refresh token and blacklists its jti. 12 / interview drill

Questions, strong answers, deeper follow-ups

1. Why Next.js plus FastAPI?

INFERRED“Next.js gives me route-based UI composition and client-side interaction; FastAPI hosts the Python services for data ingestion, analytics and AI. The boundary is JSON REST, so each side can evolve independently.”

Follow-up: What costs come with two runtimes? → Two deployables, CORS, shared API contracts and cross-origin token handling. frontend/lib/api.ts:1–77; backend/app/main.py:18–31.
2. Trace login end to end.

IMPLEMENTED“The form calls /auth/login. The service gets the user by email, verifies bcrypt hash and active status, signs access/refresh JWTs, persists refresh JTI, then returns the pair. The browser stores both and sends the access token on later requests.”

Follow-up: What happens after access expiry? → 401 triggers one refresh and retry. auth_service.py:42–54,96–100; frontend/lib/api.ts:38–77.
3. Is the dashboard cached in Redis?

IMPLEMENTED“No. Redis only stores refresh-token denylist entries. Dashboard analytics reads PostgreSQL via repositories and computes the response.”

Follow-up: When would you cache it? → Measure repeated reads, choose a short TTL, and invalidate on profile sync. core/deps.py:52–60; analytics_service.py:23–76.
4. How do you prevent users reading other users’ tutor sessions?

IMPLEMENTED“The bearer dependency establishes the active user, and ChatRepository.get_session filters by both session ID and that user's ID.”

Follow-up: Does every endpoint have ownership checks? → Review each new resource query; general authentication alone is not enough. profile_repository.py:111–126.
5. How does profile data become a roadmap?

IMPLEMENTED“Sync normalizes accepted submissions and tags into topic scores. The roadmap service selects the weakest topics, cycles them across requested weeks, combines a rating gap and curated resources, then saves the plan JSON.”

Follow-up: Is the roadmap AI-generated? → No; it is deterministic service logic. topic_analysis_service.py:4–44; roadmap_service.py:27–86.
6. What exactly does the ML model predict?

IMPLEMENTED“With at least three rating-history points, it fits a Ridge model in that request to predict rating delta; otherwise it uses a heuristic. The 3- and 6-month values extrapolate that delta. These are illustrative estimates, not validated forecasts.”

Follow-up: How would you validate it? → Historical train/test splits by user and time, MAE/calibration against baselines. prediction_service.py:14–59,104–114.
7. How is a refresh token revoked?

IMPLEMENTED“The service marks its PostgreSQL row revoked and writes the JTI to a Redis denylist. Refresh checks both before issuing a new pair.”

Follow-up: Is rotation race-safe? → Not fully; an atomic conditional update or row lock would help. auth_service.py:55–100.
8. What happens when Gemini is unavailable?

IMPLEMENTED“With no configured key, the adapter returns static fallback JSON. If a configured provider call fails at runtime, there is no explicit exception mapping in that adapter.”

Follow-up: How to improve? → Set timeout/retry budget, distinguish unavailable from fallback, validate structured output. gemini_client.py:9–23,25–68.
9. What is the most expensive request?

INFERRED“Profile sync is a likely hotspot because it waits for multiple external HTTP calls, parses submissions, deletes old rows and reinserts data before responding. I would measure latency and move it to a job if it dominates.”

Follow-up: What if a provider fails mid-sync? → The DB session rolls back, but external latency and errors still affect the request. profile_service.py:25–128; db/session.py:9–16.
10. What is the most important security change?

RECOMMENDED“First rotate the example credentials and disable public demo seeding. Then address JavaScript-readable refresh tokens, login throttling and atomic refresh rotation.”

Follow-up: Why not simply put all tokens in cookies? → Cookie transport needs SameSite, Secure, HttpOnly and a CSRF design. .env.example:1–23; frontend/lib/api.ts:17–34.
